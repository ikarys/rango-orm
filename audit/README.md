## Open findings

Campaigns of 2026-11-23 (0.5.0): no blocker. The wrong docs and the regressions are fixed (b06601a: SQLite `time` decoding and five doc fixes; 6230602: `values()` no longer returns a null for a value it cannot read), and so are the two data-integrity findings (9b78444: PostgreSQL creates `NUMERIC(P, S)`, B 1; f698ba6: MySQL import checks foreign keys and the summary counts new rows, C 2, B 11). Open, by priority (duplicates across campaigns counted once):

1. Library: `bulk_upsert` mixed-id check (A 7, C 10), negative `limit` (A 11), `atomic` future not `Send` in one case (B 5), `sum`/`avg` as `f64` on decimals (B 2), composite indexes (B 4, A 9), `in_values` typing (B 7), `bulk_create` ids (A 8), `FieldPassword` in `select_related` (A 10).
2. Messages: what timed out (A 12, C 6), migrate permission hint (A 6, B 10), empty `MIGRATE_DATABASE_URL` (B 9), `Conflict` display and column types in `Error::Invalid` (C 12, B 14), restore into a non-empty database (C 15), "did you mean" on `order_by`/`values` (C 11).
3. Docs: dates and times page, serde on models, several-backends page, atomic counter recipe, GRANT recipes, constraint names and precision per backend, large-table migrations, partial unique rule on MySQL (A 3 to 5, A 13, A 14, B 3, B 8, B 12, B 13, C 13, C 14).

Not reproduced: two slow-query `WARN` events for one statement on MySQL (2026-11-08 C #21). One `SELECT SLEEP(0.7)` gives exactly one `WARN` on `sqlx::query` on MySQL 8.4 and MariaDB 11.4, and sqlx emits it once per statement; a subscriber that also receives the same event through a `log` bridge counts it twice.
