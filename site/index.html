Rango
Guide crates.io GitHub

Your code stays simple. Rango does the hard part.

An async ORM for Rust, modelled on Django's. You declare a struct; Rango writes the SQL for PostgreSQL, SQLite and MySQL or MariaDB, generates the migrations and checks the column types in your queries at compile time.

$ cargo add rango-orm
Read the guide

Version 0.3.1, pre-1.0: a minor release may still change the API. The package is rango-orm; you import rango.

How Rango compares.

The closest is Butane, which also generates migrations from your models. Rango adds MySQL and MariaDB, model hooks and published benchmarks. Diesel can pre-fill a migration from a schema diff and SeaORM 2.0 can add missing tables at startup; Rango writes every change, renames and drops included, as a migration you review and commit.

Where Rango is weaker: a small ecosystem, and 1,000-row reads about 6% slower than raw sqlx. Checked against each project’s documentation on 2026-11-21. Full comparison in the guide.

A wrong type never reaches the database.

Columns are typed constants on the model. Compare User::AGE with a string and the build stops, with a message that names the column and the value it accepts.

Migrations are written for you.

rango makemigrations compares the models with the last schema snapshot and writes the next migration. It detects renames and gives the same file every time. On SQLite, a change that needs a table rebuild runs in one transaction.

Tested by agents that only had the docs.

Each campaign gives an AI agent a fresh context, the user guide and a real app to build, with no access to the source. It seeds 100,000 rows, runs the app's queries on them and logs every point of friction. Every finding in these reports is answered with a fix or a doc change.

Facts for your coding agent.

If an agent adds Rango to your project, these are the details it gets wrong most easily.

Package
rango-orm on crates.io, version 0.3
Import
use rango::prelude::*; (the crate name is rango)
Backends
Cargo features postgres (default), sqlite, mysql. For SQLite: rango-orm = { version = "0.3", default-features = false, features = ["sqlite"] }
Runtime
Async on sqlx; your app needs Tokio.
CLI
cargo install rango-orm-cli installs the rango binary.
Docs
The user guide and API reference on docs.rs

Safe defaults, each one tested.

Values are always bound parameters and identifiers are always quoted. Passwords are hashed with Argon2id. A remote PostgreSQL connection requires TLS unless its URL says otherwise. The security requirements list each claim with the test that proves it, and what Rango does not protect.
